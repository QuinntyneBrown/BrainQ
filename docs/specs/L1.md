# L1 - High-Level Requirements

## L1-001: Personal Knowledge Graph
The system shall store the user's personal knowledge as a graph in relational form: typed entities (Person, Project, Commitment, Note, Idea) connected by typed edges (mentions, blocks, fulfills, relatesTo). The schema must accommodate new entity and edge types without structural changes.

## L1-002: Entity Capture
The system shall allow the user to create, read, update, and delete entities of every supported type with minimal friction. Capture shall require no more than a single text input; the system shall infer entity type from the text and allow manual override.

## L1-003: Edge Management
The system shall allow the user to create, read, and delete typed relationships between any two entities.

## L1-004: Structured Query
The system shall expose structured queries over entities and edges (filter by type, attribute, date range, related entity) returning deterministic results.

## L1-005: Semantic Search
The system shall expose semantic search over entity content using vector similarity (pgvector), returning ranked results across all entity types.

## L1-006: Integration with Q-Suite
The system shall serve as the canonical store for commitments (replacing/backing the Commitments app) and contacts (replacing/backing the RecallQ app), exposing both via the same graph model.

## L1-007: Responsive UI
The system shall provide a web UI that is fully usable on viewports from extra-small (<576px) through extra-large (>=1200px), designed mobile-first. At the xl breakpoint the UI shall use the additional space for ambient context (side rail navigation, context pane) without requiring extra interaction.

## L1-008: Single-User Local Scope
The system shall operate as a single-user personal application. All data belongs to the local installation; the system shall not expose a remote sign-in surface or attempt to scope data by user identity.

## L1-009: Data Security & Privacy
The system shall protect personal data at rest and in transit and shall validate every input to defend against the OWASP Top 10.

## L1-010: Performance
The system shall return interactive responses fast enough to feel immediate on mobile networks and shall scale to tens of thousands of entities without degradation.

## L1-011: Observability & Operations
The system shall emit structured logs, health checks, and minimal metrics sufficient to diagnose failures and monitor availability.

## L1-012: Radical Simplicity
The system shall be implemented with the smallest viable architecture: a single .NET API, EF Core + Npgsql + pgvector against PostgreSQL, and one web client. No speculative abstractions, microservices, queues, caches, or layers shall be introduced unless a concrete L2 requirement demands them.

## L1-013: Daily Surface
The system shall provide a Today landing surface that orients the user each session: greeting, capture prompt, commitments due today, soft nudges drawn from the graph (overdue people, missed commitments, upcoming dates), and recently touched entities.

## L1-014: Personalization
The system shall let the user adjust visual presentation (theme, accent, density) without affecting data, with preferences persisted locally across sessions.
